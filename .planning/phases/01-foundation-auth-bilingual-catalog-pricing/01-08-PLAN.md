## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Next.js server | Untrusted URL path, query string and headers reach the server component |
| Next.js server → NestJS API | The session cookie is translated into a bearer token here; a leak or a mix-up serves one viewer's pricing to another |
| API response → rendered HTML | Staff-authored product text is interpolated into a page served to the public |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-59 | Information Disclosure | Viewer-dependent pricing served from a shared cache | mitigate | `apiGet` defaults to `cache: 'no-store'` and the catalog pages are `force-dynamic`. A dealer's wholesale price must never be cached into an anonymous visitor's response; this is enforced at the single client chokepoint rather than per-page. |
| T-01-60 | Information Disclosure | Access token leaking to the browser | mitigate | The token lives only in an httpOnly cookie read via `next/headers` inside `session.ts`, which is marked `import 'server-only'` so a client component importing it fails the build. The token is never placed in props, HTML, or a log line. |
| T-01-61 | Tampering | Stored XSS through staff-authored product name, description or alt text | mitigate | All API text is rendered as React text nodes; `dangerouslySetInnerHTML` is forbidden and asserted absent by grep in two separate tasks. Media `alt` values come from validated, length-bounded API fields. |
| T-01-62 | Tampering | Open redirect / path injection through the `[slug]` route parameter | mitigate | The slug is `encodeURIComponent`-escaped before being placed in the API path and is never used to construct a redirect target. A non-matching slug produces `notFound()`, not a redirect. |
| T-01-63 | Information Disclosure | Internal error details rendered to a visitor | mitigate | The listing page catches `ApiError` and renders a localized generic error state; the detail page maps 404 to `notFound()` and lets other errors reach the Next.js error boundary, which renders no stack trace in a production build. |
| T-01-64 | Tampering | Unvalidated query parameters forwarded verbatim to the API | accept | The API (Plan 07) validates every facet parameter with `class-validator` and returns 400 on anything malformed; duplicating that validation in the UI would create two sources of truth. The page renders the API's error state rather than crashing. |
| T-01-65 | Information Disclosure | Presigned media URLs embedded in cached HTML outliving their signature | accept | Media URLs expire after 900 seconds; with `no-store` rendering, HTML is generated per request so a served page's URLs are always fresh. A user leaving a tab open for 15+ minutes sees broken images until reload — acceptable for Phase 1, revisited if Phase 3 introduces page caching. |
