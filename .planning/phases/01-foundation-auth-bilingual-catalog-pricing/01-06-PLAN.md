<objective>
Build the pricing engine that the entire commercial side of this platform depends on, plus the minimal stock signal the storefront needs — and lock both behind a single service each, so no future code path can grow its own copy of the logic.

Purpose: PITFALLS.md Pitfall 1 and ARCHITECTURE.md Anti-Pattern 3 both name the same failure: pricing conditionals scattered across controllers and a `wholesale_price` column bolted on later. The mitigation is structural — one `PriceResolutionService`, one `PriceTier`/`PriceListEntry` table pair, and a `minQty` column that already carries Phase 4's quantity-break semantics. `VariantStockService` is the matching structural decision for Phase 2: it publishes a per-variant availability contract that Phase 2's SKU × Warehouse × Batch ledger can slot in behind without changing any caller.
Output: `PriceResolutionService`, `VariantStockService`, `/api/admin/price-tiers`, `/api/admin/variants/:variantId/prices`, `/api/admin/variants/:variantId/stock`.
</objective>
